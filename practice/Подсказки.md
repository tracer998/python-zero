Конечно. Твоя CRM может развиваться постепенно: сначала данные в памяти, затем сохранение в файл, потом классы и база данных. Не нужно сразу пытаться написать «настоящую CRM».

## 1. Модель данных

Сейчас один заказ выглядит так:

```python
{
    "client_name": "John Doe",
    "product_name": "keyboard",
    "quantity": 10,
    "price": 19.99,
    "status": "new"
}
```

Это **словарь**: у каждого значения есть понятное имя.

Все заказы хранятся в **списке**:

```python
orders_list = [
    {"client_name": "John Doe", ...},
    {"client_name": "Мария", ...}
]
```

Почему именно так:

- список хранит много заказов;
- словарь описывает один заказ;
- цикл позволяет перебрать все заказы;
- функции выполняют отдельные действия над заказами.

Это называется простой структурой данных.

## 2. CRUD

Основные действия CRM называются CRUD:

| Операция | Что делает | Твоя функция |
|---|---|---|
| Create | создать | `add_order()` |
| Read | посмотреть | `show_orders()` |
| Update | изменить | пока нет |
| Delete | удалить | `delete_order()` |

Поиск является разновидностью `Read`.

Главное правило: одна функция должна отвечать за одну задачу. Например:

```python
def add_order():
    # только создание заказа

def show_orders():
    # только отображение заказов

def find_order():
    # только поиск

def delete_order():
    # только удаление
```

Не стоит помещать всё в одну огромную функцию.

## 3. Главное меню

CRM должна постоянно ждать команду пользователя. Для этого нужен цикл `while`.

Теория:

```python
while условие:
    действие
```

Например:

```python
while True:
    print("1. Добавить заказ")
    print("2. Показать заказы")
    print("3. Найти заказ")
    print("4. Удалить заказ")
    print("0. Выйти")

    choice = input("Выберите действие: ")

    if choice == "1":
        add_order()
    elif choice == "2":
        show_orders()
    elif choice == "3":
        find_order()
    elif choice == "4":
        delete_order()
    elif choice == "0":
        break
    else:
        print("Неизвестная команда")
```

`break` прерывает цикл. Для учебной программы это лучше, чем использовать встроенный `exit()`.

Логика здесь такая:

1. показать меню;
2. получить выбор;
3. вызвать нужную функцию;
4. после выполнения вернуться к меню;
5. выйти только по команде `"0"`.

## 4. Добавление заказа

У тебя уже есть почти готовая функция:

```python
def add_order():
    order = {}

    order["client_name"] = input("Введите имя клиента: ")
    order["product_name"] = input("Введите товар: ")
    order["quantity"] = int(input("Введите количество: "))
    order["price"] = float(input("Введите цену: "))
    order["status"] = "new"

    orders_list.append(order)
```

Здесь используются:

- `input()` получает строку;
- `int()` превращает строку в целое число;
- `float()` превращает строку в дробное число;
- `append()` добавляет элемент в список.

Проблема: если пользователь напишет `abc` вместо числа, программа завершится с ошибкой `ValueError`.

Поэтому преобразование чисел нужно защищать:

```python
try:
    quantity = int(input("Введите количество: "))
except ValueError:
    print("Количество должно быть числом")
    return
```

`return` завершает текущую функцию.

Для цены полезно проверить, что значение положительное:

```python
if price <= 0:
    print("Цена должна быть больше нуля")
    return
```

То же самое для количества:

```python
if quantity <= 0:
    print("Количество должно быть больше нуля")
    return
```

## 5. Общая функция безопасного ввода

Когда одинаковая проверка встречается несколько раз, её можно вынести в отдельную функцию:

```python
def get_positive_integer(message):
    while True:
        try:
            value = int(input(message))

            if value > 0:
                return value

            print("Введите число больше нуля")

        except ValueError:
            print("Введите целое число")
```

Теперь в `add_order()` можно использовать:

```python
quantity = get_positive_integer("Введите количество: ")
```

Теория здесь важная:

- `while True` повторяет вопрос, пока ввод неправильный;
- `try` пытается выполнить опасную операцию;
- `except` перехватывает ошибку;
- `return` возвращает правильное значение из функции.

Для цены можно сделать похожую функцию с `float`.

## 6. Показ заказов

Сейчас `print(orders_list)` работает, но выглядит неудобно. Лучше выводить каждый заказ отдельно:

```python
def show_orders():
    if not orders_list:
        print("Заказов пока нет")
        return

    for index, order in enumerate(orders_list, start=1):
        total = order["price"] * order["quantity"]

        print(
            f"{index}. "
            f"Клиент: {order['client_name']}, "
            f"товар: {order['product_name']}, "
            f"количество: {order['quantity']}, "
            f"сумма: {total:.2f}, "
            f"статус: {order['status']}"
        )
```

Новые понятия:

### Проверка пустого списка

```python
if not orders_list:
```

Это означает: «если список пустой».

### `enumerate`

```python
for index, order in enumerate(orders_list, start=1):
```

Он даёт одновременно:

- номер заказа;
- сам заказ.

### Форматирование числа

```python
f"{total:.2f}"
```

Показывает число с двумя знаками после запятой.

## 7. Поиск заказа

Сначала нужно решить, по какому признаку искать. Например, по имени клиента.

Теория поиска:

1. получить запрос;
2. перебрать все заказы;
3. сравнить имя;
4. вывести совпадения;
5. если совпадений нет, сообщить об этом.

```python
def find_order():
    search_name = input("Введите имя клиента: ").lower()
    found = False

    for order in orders_list:
        client_name = order["client_name"].lower()

        if search_name in client_name:
            print(order)
            found = True

    if not found:
        print("Заказы не найдены")
```

Почему `.lower()`:

```python
"Мария".lower() == "мария".lower()
```

Так поиск не зависит от регистра букв.

Почему используется `found`:

- в начале совпадений ещё нет;
- при найденном заказе `found = True`;
- после цикла можно понять, были ли результаты.

## 8. Удаление заказа

Удалять заказ удобнее по его номеру. Сначала показать список, затем попросить номер.

```python
def delete_order():
    show_orders()

    if not orders_list:
        return

    try:
        order_number = int(input("Введите номер заказа: "))
    except ValueError:
        print("Введите число")
        return

    index = order_number - 1

    if index < 0 or index >= len(orders_list):
        print("Такого заказа нет")
        return

    deleted_order = orders_list.pop(index)
    print(f"Заказ клиента {deleted_order['client_name']} удалён")
```

Здесь важно понять разницу:

- пользователю показываем номера начиная с `1`;
- в списке индексы начинаются с `0`;
- поэтому используется `order_number - 1`.

Метод `pop()`:

```python
deleted_order = orders_list.pop(index)
```

Удаляет элемент и одновременно возвращает его.

Нельзя просто делать:

```python
del orders_list[order_number]
```

без проверки: пользователь может ввести номер, которого нет, и программа получит `IndexError`.

## 9. Изменение заказа

CRM должна уметь менять статус:

```python
def update_order_status():
    show_orders()

    if not orders_list:
        return

    try:
        order_number = int(input("Введите номер заказа: "))
    except ValueError:
        print("Введите число")
        return

    index = order_number - 1

    if index < 0 or index >= len(orders_list):
        print("Такого заказа нет")
        return

    print("Доступные статусы:")
    print("1. new")
    print("2. processing")
    print("3. paid")
    print("4. completed")
    print("5. cancelled")

    status_choice = input("Выберите статус: ")

    statuses = {
        "1": "new",
        "2": "processing",
        "3": "paid",
        "4": "completed",
        "5": "cancelled"
    }

    if status_choice not in statuses:
        print("Неизвестный статус")
        return

    orders_list[index]["status"] = statuses[status_choice]
    print("Статус изменён")
```

Здесь появляется словарь соответствий:

```python
statuses = {
    "1": "new",
    "2": "processing"
}
```

Он удобнее, чем длинная цепочка `if`.

## 10. Важное исправление для цены

Для учебного проекта `float` допустим:

```python
price = float(input("Цена: "))
```

Но в реальных системах деньги обычно не хранят через `float`, потому что дробные числа могут давать неточности.

Например, компьютер иногда хранит `0.1 + 0.2` не ровно как `0.3`.

Позже лучше использовать `Decimal`:

```python
from decimal import Decimal

price = Decimal(input("Введите цену: "))
```

Пока можешь оставить `float`, чтобы не перегружать текущий этап.

## 11. Сохранение данных

Сейчас при завершении программы список исчезает. Это потому, что он хранится только в оперативной памяти.

Следующий этап после CRUD — файл JSON.

JSON хорошо подходит для твоих словарей и списков:

```python
import json
```

Сохранение:

```python
def save_orders():
    with open("orders.json", "w", encoding="utf-8") as file:
        json.dump(orders_list, file, ensure_ascii=False, indent=4)
```

Загрузка:

```python
def load_orders():
    try:
        with open("orders.json", "r", encoding="utf-8") as file:
            return json.load(file)
    except FileNotFoundError:
        return []
```

В начале программы:

```python
orders_list = load_orders()
```

После добавления или удаления:

```python
save_orders()
```

Теория:

- `with open(...)` открывает файл и автоматически закрывает его;
- `"w"` означает запись;
- `"r"` означает чтение;
- `json.dump()` сохраняет Python-данные в файл;
- `json.load()` загружает данные из файла;
- `FileNotFoundError` возникает, если файла ещё нет.

## 12. Рекомендуемый порядок обучения

Не добавляй всё сразу. Делай этапами:

### Этап 1

- `while`;
- меню;
- `if / elif`;
- `break`.

### Этап 2

- красивый вывод заказов;
- поиск;
- удаление;
- проверка индексов.

### Этап 3

- `try / except`;
- повторный ввод через `while`;
- проверка положительных чисел;
- проверка пустых строк.

### Этап 4

- изменение статуса;
- редактирование заказа;
- расчёт общей суммы;
- подсчёт количества заказов.

### Этап 5

- сохранение в JSON;
- загрузка при старте;
- сохранение после изменений.

### Этап 6

- разделить код на файлы;
- создать отдельный модуль для заказов;
- создать отдельный модуль для меню;
- затем изучить классы и базу данных SQLite.

## 13. Как мыслить при добавлении функции

Перед написанием любой функции задавай себе четыре вопроса:

1. Что пользователь вводит?
2. Какие данные нужно найти или изменить?
3. Что произойдёт, если ввод неправильный?
4. Что функция должна вернуть или вывести?

Например, для удаления:

1. пользователь вводит номер;
2. программа находит элемент списка;
3. проверяет, что номер существует;
4. удаляет заказ и сообщает о результате.

Так ты будешь не просто копировать код, а постепенно учиться проектировать программу.

Твоя ближайшая задача: реализовать меню, затем `find_order()`, а после этого `delete_order()`. Это даст хорошее понимание циклов, условий, списков, словарей и функций на одном реальном примере.
